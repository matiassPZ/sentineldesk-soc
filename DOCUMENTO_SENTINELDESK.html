🛡️ DOCUMENTO TÉCNICO DE PROYECTO: SENTINELDESK

Enterprise Incident Management & SOC Dashboard with RBAC and Forensics

1. Resumen Ejecutivo

SentinelDesk es una solución Full Stack empresarial para la gestión y mitigación de incidentes de seguridad de la información. El sistema fue diseñado bajo el principio de menor privilegio (Principle of Least Privilege), incorporando control de acceso basado en roles (RBAC), autenticación sin estado mediante Tokens JWT, almacenamiento seguro de credenciales mediante Salted Bcrypt Hashing y un registro inmutable de auditoría forense para trazabilidad de eventos.

2. Stack Tecnológico Dominado e Integrado

Capa Tecnología Propósito
Base de Datos PostgreSQL en Neon.tech (AWS Ohio) Almacenamiento relacional serverless en la nube con alta disponibilidad.
ORM Prisma 5 (Engine estable) Mapeo objeto-relacional, migraciones declarativas y consultas tipadas.
Runtime & Servidor Node.js + Express (ESM) Servidor API RESTful de alto rendimiento configurado en módulos modernos.
Tipado Estricto TypeScript Garantía de robustez en tiempo de compilación y tipado de interfaces.
Criptografía BcryptJS + JSON Web Tokens (JWT) Hashing unidireccional y emisión de credenciales de sesión firmadas.
Frontend HTML5, CSS3 (SOC Dark Theme) y Vanilla JS Interfaz ágil, reactiva y desacoplada consumiendo la API mediante Fetch.

4. Desafíos Técnicos y Resoluciones de Ingeniería

  • Cuellos de Botella de E/S en almacenamiento externo (USB vs SSD): Se superó la lentitud de escritura en memorias externas migrando el repositorio al disco SSD local (C:\Proyectos\), acelerando las operaciones de paquetes.
  • Estabilidad del ORM (Prisma 8 RC vs Prisma 5): Se resolvió la incompatibilidad de dependencias preliminares adoptando la versión de producción estable prisma@5.
  • Alineación de Módulos ECMAScript (ESM) y TypeScript: Se solucionaron errores de compilación ajustando package.json con "type": "module" y optimizando tsconfig.json con directivas NodeNext.
  • Manejo Estricto de Parámetros de Ruta: Se resolvió la ambigüedad tipada de Express en TypeScript mediante aserción explícita (req.params.id as string).

5. Características de Seguridad Implementadas

  • Cifrado Unidireccional: Las contraseñas se almacenan mediante algoritmos de hash con salting de 10 rondas ($2b$10$...), impidiendo su recuperación en caso de brechas.
  • Autenticación sin Estado (Stateless JWT): Las sesiones se gestionan mediante tokens firmados enviados en cabeceras Authorization: Bearer.
  • Control de Acceso Basado en Roles (RBAC): Separación lógica donde los administradores y técnicos operan incidencias globales, y los usuarios estándar acceden únicamente a sus registros personales.
  • Auditoría Forense Inmutable (AuditLog): Registro persistente de inicios de sesión, creaciones y cambios de estado con IP de origen y marcas de tiempo.
